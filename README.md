# 楽天市場お気に入り商品情報取得プログラム

## 概要

楽天市場のお気に入りに登録した商品の情報を取得し、Googleスプレッドシートに追記するツールです。

Playwrightでブラウザを操作して楽天市場にログインし、お気に入りページから商品URLを集めます。各商品ページからは商品名を並列で取得します。
取得した商品は、楽天ROOM自動投稿プログラム（RakutenRoom_AutoPost）の投稿対象（PostStatus「未」）としてスプレッドシートに登録されます。

## 主な機能

- 楽天市場への自動ログイン（ログインセッションを保存し、2回目以降は入力を省略）
- お気に入り商品URLの一括収集（ページ送り対応）
- 商品ページからの商品名取得（最大3ページを並列処理。画像・CSS等は読み込まず軽量に取得）
- Googleスプレッドシートへの追記（登録済みの商品はスキップ）
- ログファイルへの処理経過・失敗理由の記録（保存先は `.env` の `LOG_DIR` で変更可能）

## プログラム構成

| ファイル | 役割 |
|---|---|
| `main.py` | メイン処理（各モジュールの統合、処理フロー全体の制御） |
| `config.py` | `.env` の読み込みと設定値・定数の管理、`user_data`・ログの保存先の決定 |
| `browser_manager.py` | Playwright（Chromium）の起動・終了、ログインセッションの保存（`user_data`）、パスキー要求のキャンセル |
| `rakuten_login.py` | 楽天へのログイン判定・ログイン処理、再認証 |
| `fetch_favorites.py` | お気に入りページからの商品URL収集、新規商品の商品ページからの商品名取得 |
| `google_sheets_utils.py` | Google Sheets APIへの接続（サービスアカウント認証）、登録済み商品コードの取得 |
| `Write_Items_Info_to_Google_Sheet.py` | 新規商品のスプレッドシートへの追記 |
| `logger.py` | ログ出力（コンソールとログファイル） |
| `.env.example` | `.env`（設定ファイル）のひな形 |
| `tests\` | 自動テスト（ブラウザ・スプレッドシートを使わずに動作を確認する） |
| `.github\workflows\tests.yml` | GitHub Actions の設定（GitHubにpushしたときに自動テストを実行する） |
| `requirements-dev.txt` | テスト用のパッケージ（pytest・pyflakes・vulture） |

### 処理フロー

```
1. スプレッドシートに接続し、登録済みの商品コード（ItemCode）を取得
   └─ 接続に失敗した場合は、ブラウザを起動せずに終了
2. ブラウザ起動（user_dataに保存されたログインセッションを読み込む）
3. 楽天へのログイン
   ├─ ログイン済み（セッションが有効）→ そのまま次へ
   └─ 未ログイン → ID・パスワードでログイン（パスキーはキャンセルしてパスワードを使用）
4. お気に入りページを開き、商品URLを収集
   └─ 再認証を求められた場合はパスワードで再認証
5. 登録済みの商品を除き、新規商品の商品ページから商品名を取得
   └─ 商品名を取得できなかった商品は登録しない（次回の実行で再取得）
6. 新規商品をスプレッドシートの末尾に追記（PostStatus・CollectionStatusは「未」）
7. ブラウザ終了
```

## 必要な環境

- Windows
- Python 3.10以上
- 楽天会員アカウント（パスワードでログインできること）
- Googleアカウント（Google Cloud のサービスアカウント、Googleスプレッドシート）

## セットアップ手順

### 1. 環境構築
```bash
# 仮想環境の作成
python -m venv venv

# 仮想環境の有効化
.\venv\Scripts\activate

# pip を最新にする（古いpipは日本語を含む requirements-dev.txt を読めずにエラーになる）
python -m pip install --upgrade pip

# パッケージのインストール
pip install -r requirements.txt

# Playwrightのブラウザをインストール
playwright install chromium
```

### 2. .env ファイルの作成
`.env.example` をコピーして `.env` という名前で保存し、各項目を書き換えます。

| 項目 | 必須 | 内容 |
|---|---|---|
| `RAKUTEN_USER_ID` | ○ | 楽天会員のユーザーIDまたはメールアドレス |
| `RAKUTEN_PASSWORD` | ○ | 楽天会員のパスワード |
| `SPREADSHEET_ID` | ○ | スプレッドシートのID（URLの `/d/` と `/edit` の間） |
| `SHEET_NAME` | | シート名（省略時は `Sheet1`） |
| `SERVICE_ACCOUNT_PATH` | ○ | サービスアカウントのJSONキーのパス（相対パスは `.env` のあるフォルダ基準） |
| `LOG_DIR` | | ログの保存先フォルダ（省略時はプログラムのフォルダの `logs`。相対パスはプログラムのフォルダ基準） |
| `PLAYWRIGHT_BROWSERS_PATH` | | Playwrightのブラウザのインストール先（通常は指定不要） |

> **Windowsのパスはシングルクォートで囲んでください。**
> ダブルクォートで囲むと `\r` や `\n` が改行文字として解釈され、パスが壊れます（例: `...\rakuten.json` の `\r`）。
> ダブルクォートを使う場合は `\\` と重ねるか、`/` 区切りで書いてください。
> ```
> SERVICE_ACCOUNT_PATH='C:\Users\you\service_account.json'   ← OK
> SERVICE_ACCOUNT_PATH="C:\Users\you\service_account.json"   ← NG
> ```

ヘッドレスモード（ブラウザ画面を表示しない）は `.env` ではなく `config.py` の `HEADLESS_MODE` で設定します。

### 3. Google認証の設定
1. Google Cloud Console でプロジェクトを作成し、Google Sheets API を有効にする
2. サービスアカウントを作成し、JSONキーをダウンロードする
3. ダウンロードしたJSONファイルのパスを `.env` の `SERVICE_ACCOUNT_PATH` に設定する
4. 対象のスプレッドシートを、サービスアカウントのメールアドレス（JSON内の `client_email`）に「編集者」として共有する

### 4. スプレッドシートの準備
シートが空の場合は、初回実行時に次の見出しを1行目に自動で追加します。

| 見出し | 内容 | このプログラムで記入する値 |
|---|---|---|
| `ItemURL` | 楽天市場の商品ページのURL | ○ |
| `ShopCode` | ショップコード | ○ |
| `ItemID` | 商品ID | ○ |
| `ItemCode` | 商品コード（`ショップコード:商品ID`） | ○ |
| `ItemName` | 商品名 | ○ |
| `CollectionName` | コレクション名 | 空欄 |
| `CollectionGenre` | コレクションのジャンル | 空欄 |
| `PostStatus` | ROOMへの投稿ステータス | `未` |
| `PostedDate` | 投稿日 | 空欄 |
| `CollectionStatus` | コレクション登録ステータス | `未` |
| `CollectedDate` | コレクション登録日 | 空欄 |

- 見出しはA〜K列の範囲内であれば列の順番は問いません（見出し名で列を判定します）。見出し名は完全一致させてください。
- `ItemCode` 列は必須です。見出しに無い場合はエラーで終了します。
- 登録済みの商品（`ItemCode` が一致する商品）は追記しません。既存の行は上書きしません。
- お気に入りから削除した商品も、スプレッドシートには残ります。
- 商品名は商品ページの `meta[itemprop="name"]` から取得します。無い場合はページタイトル（「【楽天市場】商品名：ショップ名」）から商品名の部分を取り出します。

## 実行方法

### 通常実行
```bash
python main.py
```

- 実行するとブラウザ（Chromium）の画面が開き、自動で操作されます。操作中は画面に触れないでください。

### 自動テスト

ブラウザやスプレッドシートを使わずに、プログラムの動作を確認できます。楽天にもスプレッドシートにも接続しないので、何度実行しても問題ありません。
コードを修正したときに実行してください。

```powershell
pip install -r requirements-dev.txt     # 初回のみ（pytest などテスト用のツールを入れる）
python -m pytest tests
```

`61 passed` のように表示され、`failed` が無ければ問題ありません。

主に次のことを確認しています。

| テストファイル | 確認していること |
|---|---|
| `test_fetch_favorites.py` | お気に入りURLの収集・重複除去・ページ送りの終了（無限ループしない）、登録済み商品のスキップ、商品名の取得と「【楽天市場】」等の除去、商品名が取れない商品を登録しないこと、ページの使い回しと後片付け |
| `test_rakuten_login.py` | ログイン画面の操作の順番（ID → パスワードを使用する → パスワード、再認証の確認画面）、ID・パスワードを1回しか送信しないこと（アカウントロック防止） |
| `test_google_sheets.py` | 登録済み商品コードを見出し名で取得すること、見出しの順番どおりに追記すること、追加した商品のログ |
| `test_main.py` | 接続失敗時にブラウザを起動しないこと、失敗時に書き込まず「完了」と記録しないこと、必ずブラウザを閉じること |
| `test_config_logger.py` | ログの保存先（`LOG_DIR`）、cp932の画面でも止まらないこと |

コードの誤り・使っていないコードのチェックも、GitHub Actions と同じコマンドで実行できます。

```powershell
python -m pyflakes *.py tests/*.py
python -m vulture *.py tests/*.py --min-confidence 60
```

何も表示されなければ問題ありません。

#### GitHubでの自動テスト（GitHub Actions）

GitHubにpush（またはプルリクエストを作成）すると、GitHub上で自動的に上記のチェックとテストが実行されます（設定ファイル: `.github/workflows/tests.yml`）。
楽天やスプレッドシートには接続しないため、`.env` やJSONキーをGitHubに置く必要はありません（置かないでください）。

- 結果の見方: GitHubのリポジトリの「Actions」タブを開くと、実行ごとに ✅（成功）か ❌（失敗）が表示されます。❌ をクリックすると、どのテストが失敗したか確認できます。
- 手動で実行: 「Actions」タブ →「テスト」→「Run workflow」
- 失敗したときは、パソコンで `python -m pytest tests` を実行して同じエラーが出るか確認し、修正してから再度pushしてください。

### ログインとセッションの保存（user_data）
- ログイン状態は `user_data` フォルダに保存され、2回目以降の実行ではID・パスワードの入力を省略します。
  - `python main.py` 実行時: プロジェクト直下の `user_data`
  - `.exe` 実行時: `RakutenFavorite.exe` と同じフォルダの `user_data`
- 初回（`user_data` が無い・中身を削除した）や、セッションが切れている場合は自動でログインします。
  - 楽天からパスキー認証を求められますが、自動でキャンセルしてパスワードでログインします（パスキーのQRコードは表示されません）。
- お気に入りページの表示時に楽天から再認証を求められることがありますが、自動でパスワードを入力して続行します。
- ログイン状態をリセットしたい場合は `user_data` フォルダを削除してください。
- `user_data` にはログイン情報（Cookie）が含まれるため、他人に渡したりGitにコミットしたりしないでください（`.gitignore` で除外済み）。
- `user_data` を使用中のブラウザは同時に1つしか起動できません。このプログラムを2つ同時に実行しないでください。

## 実行ファイル（.exe）の作成

Pythonが入っていないパソコンでも動かせるように、プログラムを1つの実行ファイル（`RakutenFavorite.exe`）にまとめます。
タスクスケジューラで定期的に自動実行する場合も、この実行ファイルを使います。

> **コードを修正したときは、必ず実行ファイルを作り直してください。** 作り直さないと、修正は実行ファイルに反映されません。

### 1. 実行ファイルを作成する手順

**事前準備**: 「[セットアップ手順](#セットアップ手順)」を済ませ、`python main.py` で動くことを確認しておいてください。

**手順1. プロジェクトのフォルダでターミナルを開く**

エクスプローラーでプロジェクトのフォルダ（`main.py` があるフォルダ）を開き、フォルダ内の何もないところを右クリックして「ターミナルで開く」を選びます。
（表示されない場合は「その他のオプションを確認」→「ターミナルで開く」を選びます。または PowerShell を起動して、次のように `cd` でフォルダに移動します。）

```powershell
cd "C:\path\to\Rakuten_Favorite_Product_Information_Retrieval"
```

**手順2. 仮想環境を有効にする**（仮想環境を作っている場合）

```powershell
.\venv\Scripts\activate
```

行の先頭に `(venv)` と表示されれば有効になっています。

**手順3. PyInstaller をインストールする**（初回のみ）

実行ファイルの作成には PyInstaller というツールを使います（`requirements.txt` には含まれていないため、別途インストールします）。

```powershell
pip install pyinstaller
```

**手順4. 実行ファイルを作成する**

初めて作成するとき（フォルダに `RakutenFavorite.spec` が無いとき）は、次のコマンドを実行します。

```powershell
pyinstaller --onefile --name RakutenFavorite main.py
```

2回目以降（作り直す場合）は、1回目に作られた設定ファイル（`RakutenFavorite.spec`）を使って次のコマンドで作成します。

```powershell
pyinstaller --noconfirm --clean RakutenFavorite.spec
```

- 1〜2分ほどかかります。最後に `Build complete!` と表示されれば成功です。
- 作り直すときは、実行中の `RakutenFavorite.exe` を終了してから実行してください（実行中は上書きできません）。
- `--clean` は前回の作業データを消してから作り直すオプションです。付けないと、変更が無いと判断されて作り直されない場合があります。
- `RakutenFavorite.spec` は `.gitignore` で除外しているため、Gitから取得し直した場合はありません。その場合は初回のコマンドを使ってください。

> **「PermissionError: [WinError 5] アクセスが拒否されました」と表示された場合**
> プロジェクトのフォルダが OneDrive の中にあると、同期中のファイルを消せずに失敗することがあります。
> 作業用のフォルダを OneDrive の外（一時フォルダ）にして作成してください。
> ```powershell
> pyinstaller --noconfirm --clean --workpath "$env:TEMP\rf_build" RakutenFavorite.spec
> ```

**手順5. できあがったファイルを確認する**

```
Rakuten_Favorite_Product_Information_Retrieval\
├─ dist\
│   └─ RakutenFavorite.exe   … できあがった実行ファイル
├─ build\                    … 作成時の作業フォルダ（削除してもよい）
└─ RakutenFavorite.spec       … 作成時の設定ファイル（作り直しで使う）
```

**手順6. 必要なファイルを配置して試しに実行する**

1. 「[2. 実行時に必要な外部ファイル](#2-実行時に必要な外部ファイル)」のとおり、`dist` フォルダに `.env` などを配置します。
2. `RakutenFavorite.exe` をダブルクリックして実行します。
   - 黒い画面（コンソール）とブラウザが開き、自動で処理が進みます。処理が終わると自動で閉じます。操作中は画面に触れないでください。
   - 初回はID・パスワードでログインします（`dist\user_data` にログイン状態が保存され、2回目以降は省略されます）。
   - **新しいお気に入り商品があれば、実際にスプレッドシートに追加されます。**
3. `dist\logs` フォルダにできたログファイルをメモ帳などで開き、`楽天市場お気に入り商品情報取得プログラムが完了しました` と記録されていること、`[ERROR]` が無いことを確認します。

### 2. 実行時に必要な外部ファイル
実行ファイルと同じフォルダに `.env` を配置してください。`config.py` は実行ファイルのあるフォルダの `.env` を探して読み込みます。

```
dist\
├─ RakutenFavorite.exe
├─ .env                    … .env.example をコピーして作成
├─ service_account.json    … SERVICE_ACCOUNT_PATH で指定（同じフォルダに置くのが簡単）
├─ user_data\              … 初回実行時に自動作成（ログインセッション）
└─ logs\                   … 実行時に自動作成（ログファイル。LOG_DIR指定時はそのフォルダ）
```

- `.env` の `SERVICE_ACCOUNT_PATH` を相対パス（例: `'service_account.json'`）で書いた場合は、`.env` のあるフォルダを基準に探します。
- 別のパソコンに移す場合は、`dist` フォルダの中身（`user_data` と `logs` を除く）をまとめてコピーします。

### 3. Playwright のブラウザが必要
実行ファイルでも Playwright のブラウザ（Chromium）がインストールされている必要があります。
開発に使ったパソコンでは「[1. 環境構築](#1-環境構築)」でインストール済みです。

- Windows では通常、次のフォルダにインストールされ、実行ファイルはこのフォルダを自動で使用します。
  - `%LOCALAPPDATA%\ms-playwright`（例: `C:\Users\<ユーザー名>\AppData\Local\ms-playwright`）
- `.env` の `PLAYWRIGHT_BROWSERS_PATH` を指定した場合は、そのパスを優先します。
- 別のパソコン（Pythonが無いパソコン）で使う場合は、開発用のパソコンの `ms-playwright` フォルダをコピーし、`.env` の `PLAYWRIGHT_BROWSERS_PATH` でその場所を指定してください。
  - 実行ファイルに含まれる Playwright（1.40.0）に対応したブラウザ（`chromium-1091`）が必要です。

### 4. タスクスケジューラで定期実行する場合

1. スタートメニューで「タスク スケジューラ」と検索して起動します。
2. 右側の「タスクの作成」をクリックします。
3. 「全般」タブ
   - 名前: 分かりやすい名前（例: `楽天お気に入り取得`）
   - 「ユーザーがログオンしているときのみ実行する」を選択します（ブラウザの画面を表示して操作するため）。
4. 「トリガー」タブ →「新規」
   - 実行する頻度と時刻（例: 毎日 17:30）を設定して「OK」。
   - 楽天ROOM自動投稿（RakutenRoomAutoPost）も定期実行している場合は、このプログラムが先に終わるよう、投稿より前の時刻にすると、追加した商品をその日の投稿対象にできます。
5. 「操作」タブ →「新規」
   - 操作: 「プログラムの開始」
   - プログラム/スクリプト: `RakutenFavorite.exe` のフルパス（「参照」ボタンで選べます）
   - 開始（オプション）: `RakutenFavorite.exe` があるフォルダ（省略してもログと `user_data` は exe と同じフォルダに保存されますが、指定しておくと確実です）
6. 「OK」で保存します。一覧のタスクを右クリック →「実行する」で、すぐに試せます。

- ログと `user_data` は「開始（オプション）」の設定に関係なく、`RakutenFavorite.exe` と同じフォルダ（`LOG_DIR` 指定時はそのフォルダ）に保存されます。
- 実行結果は `logs` フォルダのログファイルで確認してください。

## ログ出力

ログファイルの保存先は次のとおりです。実行時の作業フォルダ（タスクスケジューラの「開始」など）には左右されません。

| 条件 | 保存先 |
|---|---|
| `.env` に `LOG_DIR` を指定 | 指定したフォルダ（相対パスはプログラムのフォルダ基準。フォルダが無ければ作成） |
| 未指定で `python main.py` 実行 | プロジェクト直下の `logs\` |
| 未指定で `.exe` 実行 | `RakutenFavorite.exe` と同じフォルダの `logs\` |

- ファイル名: `rakuten_favorite_YYYYMMDD_HHMMSS.log`（1回の実行につき1ファイル）
- ログイン処理（セッションの利用、ID・パスワード入力、パスキーのキャンセル、再認証）の経過と失敗理由も記録されます。
- 取得件数（お気に入りのURL数、新規・登録済みの件数、スプレッドシートへの追加件数）、追加した商品（商品コード・商品名）、商品名を取得できなかった商品も記録されます。

```
[INFO] お気に入り商品のURLを120件取得しました
[INFO] 新規商品: 3件 / スキップ（登録済み）: 117件
[WARNING] 商品名を取得できなかったため、今回は登録しません: https://item.rakuten.co.jp/xxx/yyy/
[INFO] ✓ 2件の新規商品をスプレッドシートに追加しました
[INFO] 追加した商品: book:15992304 / 美容常識の9割はウソ
[INFO] 追加した商品: book:16060425 / 美肌成分事典
```

## トラブルシューティング

### 楽天へのログインに失敗する
- ログファイルの `[ERROR]` の行で原因を確認してください。
- 「パスワードを送信しましたがログインできませんでした」「ユーザーIDを送信しましたが次の画面に進めませんでした」
  - `.env` の `RAKUTEN_USER_ID`・`RAKUTEN_PASSWORD` が正しいか確認してください。
  - アカウントロックを防ぐため、ID・パスワードの送信は1回のログイン処理につき1回だけ行い、失敗しても再送信しません。
- 改善しない場合は `user_data` フォルダを削除してから再実行してください（ログインし直します）。

### スプレッドシートに接続できない
- `SERVICE_ACCOUNT_PATH` のJSONファイルが存在するか確認してください。
- エラーに `Invalid argument` と出てパスが崩れている場合は、`.env` のパスをシングルクォートで囲んでください（[.env ファイルの作成](#2-env-ファイルの作成) 参照）。
- スプレッドシートがサービスアカウントのメールアドレスに共有されているか確認してください。
- 「必須列 'ItemCode' が見つかりません」と出た場合は、1行目の見出しを確認してください。

### 商品情報が取得できない
- 「お気に入り一覧が表示されませんでした」と出た場合は、楽天市場のページ構造が変わっていないか確認してください。
- ログファイルの `[ERROR]`・`[WARNING]` の行で失敗した商品と原因を確認してください。
- 商品名を取得できなかった商品はスプレッドシートに登録されず、次回の実行で再度取得します。

### ブラウザが起動しない
- `playwright install chromium` でブラウザをインストールしてください。
- 同じ `user_data` を使うブラウザ（このプログラム）がすでに起動していないか確認してください。

## 制限事項

- 楽天市場の仕様変更により動作しなくなる可能性があります。
- 短時間に大量のリクエストを送ると楽天から制限される可能性があります。
- 1回の実行で収集するお気に入り商品のURLは最大200件（登録済みの商品を含む）です（`main.py` の `max_items`）。
- お気に入り一覧のページ送りは最大50ページです（`fetch_favorites.py` の `MAX_FAVORITE_PAGES`）。
